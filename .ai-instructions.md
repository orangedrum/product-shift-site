# ProductShift & User Mirror: AI Instructions & Guardrails

## 1. Core Tech Stack
- **Frontend:** React, TypeScript, Vite, Tailwind CSS.
- **Design System:** Neo-Brutalist (High contrast, thick black borders, hard shadows).
- **Backend:** Node.js (Express), TypeScript.
- **Database/Auth:** Supabase.
- **Payments:** Stripe (Checkout + Webhooks).
- **Email:** Resend (API-based, verified root domain `theproductshift.com`).
- **AI:** Google Gemini (`@google/generative-ai`).
- **Testing:** Playwright E2E.

## 2. UI Standards & Styleguide Mandate
- **THE STYLEGUIDE LAW:** ALWAYS refer to the existing styleguide (`frontend/src/pages/StyleGuidePage.tsx`).
- **COMPONENT DEFAULTING:** If a component is requested (Buttons, Cards, Modals), and one exists in `frontend/src/components/`, you MUST use it. 
- **NO UI INVENTION:** Do not invent new color values or border radius patterns. Base all new UI work on existing styles (e.g. `marketing-gradient`, `font-black`, `rounded-xl`).
- **Borders:** Always use `border-2 border-black` or `border-4 border-black`.
- **Shadows:** Use hard shadows, never soft. Example: `shadow-[4px_4px_0px_0px_#000]` or `shadow-[8px_8px_0px_0px_#000]`.
- **Components:** Use `NeoCard` and `NeoButton` components found in `frontend/src/components/`.
- **Typography:** Use font-black for headings. Use high-contrast text (Gray-900 or Black).
- **Responsiveness:** Mobile-first. Use `md:` prefixes for desktop layouts.

## 3. Backend & API Rules
- **Authentication:** Always use the `authenticateRequest` middleware for protected routes.
- **Public URLs:** Never hardcode base URLs. Always use the `getPublicUrl(req)` helper from `services.ts` to ensure branch-agnosticism (localhost vs staging vs prod).
- **Timeouts:** Backend AI handlers must have a 58s "Graceful Timeout" to align with Vercel's 60s limit.
- **Error Handling:** Wrap async handlers in try/catch. Return JSON in the format `{ success: false, error: "Friendly Message", details: "technical_info" }`.
- **CORS:** Origin is set to `true` with `credentials: true`.

## 4. Business Logic: The Credit & Referral System
- **Base Credit Value:** 1 Full UX Test = 3 Credits.
- **New User Gift:** Automatically grant 5 credits to new `customers` rows.
- **Referral Reward:**
  - Referee (Friend) gets 3 credits immediately upon claiming a valid code.
  - Referrer (Sender) gets 3 credits **ONLY AFTER** the referee runs their first test.
  - Prevent Self-Referral: Backend must check that `referrerEmail !== userEmail`.
- **Payment Pricing:**
  - $14 = 9 Credits (3 Tests).

  - Monthly Starter = 30 Credits/Month.

## 6. Hallucination Prevention
- **Dependency Guard (The Slopsquatting Protocol):** 
  - Never suggest a library not in `package.json` unless it is a well-known, industry-standard package (e.g., `lodash`, `date-fns`).
  - If a new library is suggested, you MUST provide the link to the official npmjs.com page so the user can verify its legitimacy.
- **Icon Guard:** Only use icons from `lucide-react`. Ensure they are imported at the top of the file.
- **Strict Type Safety:** Never use `any` for Stripe Events or Supabase payloads. Use the provided types from the libraries.
- **Environment Access:** Always use `process.env.VAR_NAME` directly; do not create intermediate local config objects that can fall out of sync.
- **Stripe Signature Guard:** Never skip the `stripe.webhooks.constructEvent` check.
- **Stripe Webhooks:** Always use `express.raw({type: 'application/json'})` for the webhook route to preserve signature verification.
- **Rate Limiting:** Public endpoints that incur costs (AI, Stripe, Resend) must be rate-limited to prevent wallet-drain attacks.
- **Security Headers:** Use `helmet` middleware in the Express backend to prevent common injection attacks.
- **Supabase Service Key:** Never expose `SUPABASE_SERVICE_KEY` on the frontend. Use it only in the backend.
  - **Note:** Support both `SUPABASE_SERVICE_KEY` and `SUPABASE_SERVICE_ROLE_KEY` for environment compatibility.
- **E2E Testing:** Playwright tests must use `baseURL` from config. In CI, use `workers: 2` and `timeout: 90000`.

## 12. Deductive Engineering & No Assumptions

- **Log Access:** If build or runtime errors persist, always ask the user for Vercel/GitHub logs before attempting further code changes.
- **Tree-First Mandate:** NEVER assume the existence or casing of a file. If a build fails with a "not defined" or "already declared" error, immediately ask the user for a fresh file tree (e.g., `git ls-files`) to check for casing collisions (e.g., `CareerAdmin.tsx` vs `careeradmin.tsx`).
 - **Architecture Awareness:** This is a monorepo-style project. The `backend/` and `frontend/` directories have their own `package.json` and `tsconfig.json` files. NEVER assume a root dependency applies to the backend. Always verify which `package.json` governs the code being modified.
- **Context Verification:** If you are unsure about the existence of a file in a sub-directory, ASK the user to provide the directory tree or specific file content before making assumptions.
- **Anti-Bypass Rule:** Never use `@ts-ignore` on imports. If a module resolution fails, use `require()` or fix the `@types` in `package.json`. Hiding build errors often leads to runtime crashes (500s).
- **Branch Agnosticism:** Always assume the code might be running in a "Secret-less" environment (like a CI runner or a PR preview). Provide bypasses for critical E2E tests.
- **Strict Absolute Paths:** Always use the full absolute paths provided in the context for all file modifications.

## 10. Anti-Hallucination & Technical Truths
- **The Law of the Seen:** Do not suggest calling a function or endpoint unless you have verified its existence in the current context's file list.
- **Circular Dependency Guard:** Never allow `index.ts` and a controller (like `analysis-controller.ts`) to import from each other. Shared logic MUST move to `services.ts`.
- **Dependency Purity:** Before suggesting an import, check `package.json`. If it's not there, provide the `npm install` command first.
- **Tailwind Enforcement:** Do not invent Tailwind classes (e.g., `text-brand-blue`). Only use standard Tailwind colors or those explicitly defined in `tailwind.config.js`.
- **Icon Strictness:** Only use `lucide-react`. If an icon is suggested, it MUST be added to the import list at the top of the file.
- **Placeholder Ban:** Never provide "..." or "// logic goes here" in a diff unless specifically asked for a snippet. Always provide the full, working implementation.
- **State Management:** Use React `useState` and `useEffect`. Do not suggest Redux, Zustand, or other libraries unless they appear in `package.json`.
- **Response Schema:** All API responses must strictly follow the `{ success, data, error, details }` structure.
